# 工具怎么设计才方便 AI 调（实测经验）

> 来源：2026-09-23 一晚把 `dsh-miliastra` 从 `0.0.3` 推到 `0.0.10` 的实况。
> 所有数字都是**真机测出来的**，所有「事故」都是**真的踩过**的。不是设计感想。

这个技能原本只教「怎么把插件装上」（挂载、契约、生效边界）。但那只解决「**能不能调**」。
一晚之后发现真正决定成败的是三件事：**读一遍描述能不能调对**、**一次调用能不能拿到想要的**、
**返回值不值得那点上下文**。这一页就是这三件事的实测结论。

---

## 0. 先记住：插件的消费者有两类，别只顾一类

| 消费者 | 看什么 | 你要给什么 |
|---|---|---|
| **人** | 面板 / 按钮 / 提示 | 看得懂的状态、别自己删东西 |
| **AI** | **工具的 `description` + `parameters` + 系统提示段**（仅此两条通道是自动到达的），以及每次调用的**回执** | 能照抄的调用、一次到位的链条、值得那点上下文的返回 |

**AI 侧的「调用体验」本身就是功能。** 判据不是「能不能调」，而是：

1. **读一遍描述，能不能照着把参数填对？**
2. **一次调用，能不能拿到我想要的东西？**
3. **这个返回，值不值它占的那点上下文？**

下面 13 条，每条都对应一个当场暴露的问题。

---

## 1. 参数名不许撞车（中文里同名的东西，必须造两个词）

**事故**：`op=levels` 同时有两个「关卡」——`level` 是**地图关卡 ID**（哪张图），`which` 是**玩法里的第几关**。
中文里两个都叫「关卡」，**参数名撞车 = 调用方一定会填错**，而且填错了不报错（类型都是 string）。

**做法**：

- 改名 `which` → **`stage`**；
- **两处**参数描述里互相点名：「`level` = **地图关卡 ID / 品牌**（哪张图，不是玩法里的第几关 —— 那个用 `stage`）」；
- **用测试钉住**：遍历所有工具，断言 `JSON.stringify(parameters)` 里**不再出现** `"which"`。

> 推论：**同一个词指两个东西时，不要靠文档解释，要造两个不同的词。** 文档会被跳过，参数名不会。

---

## 2. 返回：默认给全量，但必须能瘦身

**实测数字**：`op=levels` 返回 3 关的**每块平台坐标**，JSON **18 917 B**（≈5k tokens）。
可调用方当时想问的只是「**哪一关值得钻进去**」—— 那堆坐标纯属负担。

**做法**：加 `summaryOnly:true`，一关压成一行数字 → **3 126 B（17%）**。
再配 `stage=3` 收敛到一关（4 500 B）。

**三条硬规矩**：

| 规矩 | 为什么 |
|---|---|
| **默认行为一个字节都不改** | 想省就显式传；**不偷偷改语义**（否则老调用方的假设全变了） |
| **瘦身只能去体积，不能去结论** | `metrics` 去掉 10 个直方图分箱，但 **`core`（集中区）与 `hotBin`（热区）必须留** —— 那才是要看的两个数 |
| **测试要同时断言「省下来了」AND「数字还在」** | 只断言前者，写成「把所有字段删光」也能过 |

> 经验：AI 的自然节奏是**先摘要、再钻取**。
> 给「`summaryOnly` + 收敛参数（`stage=N` / `run=<epoch>` / `limit`）」，比给一个巨大的全量返回有用得多。

---

## 3. 描述：给一条**可照抄的调用**，而不是一堆「为什么」

**做法**：每个工具的 `description` 末尾加一行：

```
**典型调用**：`{"op":"levels","summaryOnly":true}`（先扫全部关卡几何）
            → `{"op":"levels","stage":3}`（再钻第 3 关）
```

**理由**：description 是 AI 唯一一定读的东西。讲「为什么」帮它**判断该不该用**；
给「典型调用」帮它**直接调对**。两者都要，但**别只给前者**。

**用测试钉住**：断言**每个**工具的 description 都含「典型调用」—— 加新工具时会忘，测试不会。

---

## 4. 判据只能有一份（漂移过的判据比没有判据更坏）

**情境**：`miliastra_playtest op=wait`（等开跑）与 `miliastra_shot op=burst awaitPlaytest:true`（等开跑后连拍）
都要判「试玩开跑了」。**两条路各写一套 = 早晚漂移**，而**漂移过的判据比没有判据更坏** ——
调用方会相信错的那一份。

**做法**：抽成 `waitForPlaytestStart()`，两条路共用；**抽完立刻跑一次回归**
（`op=wait` 超时仍能被打断、仍回 `hit:false`），证明重构没改行为。

> 推广：凡是「两个入口要做同一件判断」的，抽函数 + 跑回归，成本几分钟，收益是永久一致。

---

## 5. 一次调用 > 两次调用（时间敏感的链条必须内聚）

**实测数字**：需求是「等试玩开跑 → 再等 3 秒 → 连拍 5 张」。
拆成两次调用（先 `playtest op=wait`，再 `shot`）时，**两次调用之间的往返延迟 1~3 秒**
会直接毁掉时间精度 —— 而连拍的全部意义就在时间上。

**做法**：`miliastra_shot {"op":"burst","awaitPlaytest":true,"afterSec":3,"count":5}` **一次完成**。
默认 `awaitPlaytest:false`（不阻塞、行为可预期），需要时序时才开。

> 推论：**时间敏感的多步链 → 一次调用**；**不需要时序的步骤 → 拆开更灵活**。
> 别一律合，也别一律拆，看「中间那段时间有没有意义」。

---

## 6. 回执要自证；**参数名骗人时，回执必须当场纠正**

回执的职责是让调用方**自己确认「拿到的是不是我要的那个东西」**：

| 能力 | 回执里必须有什么 |
|---|---|
| 截图 | `pid / process / title / candidates[]` —— 「截到的到底是哪个窗口」 |
| 连拍 | **`measuredIntervalMs`（实测帧距）** + 每张的 `elapsedMs` |
| 读日志 | `scanned / ignored`（忽略了几条要如实报） |
| 等信号 | 超时**不抛错**，回 `hit:false` + `timedOut:true` |

**最贵的一类误解：参数看起来是那个意思、其实不是。**
实测：`burstMs=800` 看着是「每 0.8 秒一张」，真实帧距是 **2600ms** ——
因为它只是**两张之间的额外等待**，没算单张自身耗时（本机起 PowerShell + `PrintWindow` + 顺带缩略图 ≈ 2.6 秒/张）。

纠正方式（三条一起上）：

1. 参数描述里写明「这只是**额外等待**」；
2. 回执**恒定**给 `measuredIntervalMs`；
3. 实测值 > 请求值 1.5 倍时，`note` 里直接说「**差额是单张自身耗时，不是没生效**」。

> 还有一条：**二进制不进 JSON**。截图回执只给路由入口
> （`GET /<prefix>/shot?name=<file>` 原图、`&thumb=1` 小图），**不带 base64**。

## 7. 危险操作：默认安全 + 先给计划

| 模式 | 例子 |
|---|---|
| **`dryRun` 先给计划** | `op=burst dryRun:true` → 先告诉你「拍几张、要多久、当前帧距多少」，**一张都不拍** |
| **默认只报告、真删双钥匙** | `op=clean` 默认 `dryRun`；真删要 `dryRun:false` + `confirm:true` |
| **不需要动就一个字节都不动** | `fixbom` 遇到「本来就没有 BOM」→ **连 mtime 都不碰**，并如实回「什么都没做」 |
| **不可逆动作也给退路** | 覆盖前后都留备份，回执恒带 `restoreWith` |

> 判据：**默认行为要是「不会造成后果的那一个」**；要造成后果，得调用方再点一次头。

---

## 8. 静默忽略 vs 大声报错：按「谁错了」区分

| 情况 | 怎么做 |
|---|---|
| **调用方的输入非法**（未知 op、数值离谱、路径不对） | **大声报错** + 给出可用取值 |
| **数据里混着无关内容**（日志里没有指标格式的行） | **静默忽略**，并把 `ignored` 计数**如实报出** |

**反过来就糟**：对无关数据报错 → 人不敢开这个功能；对非法输入静默 → 人以为生效了。

---

## 9. 不猜：认不出来就说认不出来

- 受限解析（用户脚本里的表）遇到**算出来的值**（算术 / 拼接 / 函数调用）→
  **报行号 + 那一行原文**，绝不猜。
  > ⚠️ **静默少算一块比报错更坏** —— 它看起来是成功的。
- 没有部署记录 → 说「**没有**」，不假装一致（`hasFingerprint:false`）。
- 对账对不了（没有 `.gil`）→ 说「**对不了账**」，且**下一步里不许出现「可以试玩了」**。

---

## 10. 只报数字，不下判决

工具给「**水平投影重叠 20px / 头顶净空 6px / x 集中区 502~703**」，
**不给**「这关有问题 / 跳不过去」。

理由：阈值是**业务方**定的（跳跃初速、重力、判定容忍）。工具越界下判决，等于替用户改玩法。

**用测试钉住**：断言输出对象里**没有** `pass` / `reachable` / `verdict` / `issue` 这类字段名。
（顺带还会逼你检视：某个字段名是不是在偷偷下结论。）

## 11. 测试纪律（给 AI 设计的工具，测试要这么写）

| 规矩 | 真实教训 |
|---|---|
| **不许占用户磁盘** | 连拍测试**故意不真拍**（每张 2.6 秒 + 往用户目录写 2.4MB）；真机证据留**一次性手工跑** |
| **别让断言自己踩自己** | 「回执里不含 base64」这条断言**失败**了 —— 因为 `note` 里**写着**「不带 base64」这句人话。断言要断**实质**（无超长串 / 无 `data:` URI / 总长 < N），不是断子串 |
| **不确定的排序要兜底** | 连拍截图 `mtime` 可能落在**同一毫秒** → 只按 mtime 排会退化成「readdir 什么顺序就什么顺序」，面板每次刷新顺序都变、测试**偶发失败** → 按名字倒序兜底 |
| **断言要查「对的位置」，不只是「存在」** | 「提示段覆盖了 7 个工具」第一版写成 `text.includes(工具名)` → **假通过**：工具名在第一行的工具清单里就有，于是「每条 bullet 根本没带工具名」也照样绿 —— 渲染出来是「· 先用它定位…」，**读的人不知道「它」是谁**。→ 改成**按行**查「`工具名：`」。**同一个"断错对象"的坑，一轮里踩了两次**（另一次见上一行） |
| **不变量的测试比功能测试更值钱** | 功能测试证明「这个功能对」；**不变量测试防止下一个人把它改坏**。例：每个工具都有典型调用 / 没有撞车参数名 / `summaryOnly` 真省且不丢数字 |
| **测试跑手必须显式设退出码** | 本技能自己的 `test-skill.mjs` 就踩了：结尾**没有 `process.exit`** → 「3 项失败」也照样 `exit 0`。接进 CI 或 `if ($LASTEXITCODE) {}` 时**完全看不出来**（实测就是这么被瞒过一次）。**不会失败的测试比没有测试更坏** —— 它训练人忽略测试 |
| **测试跑手别用管道看结论** | `node x.mjs \| Select-Object -Last 3` 报出的 exit code **不是** node 的（见附录）→ 另跑一次看 `$LASTEXITCODE` |

## 12. 系统提示段是**第二条通道**（别只写工具）

**工具 schema** 与**系统提示段**（`systemPrompt.section`）是仅有的两条能自动到达模型的通道；
**面板、HTTP 路由、README、CHANGELOG —— AI 都看不见**（除非你在对话里贴给它/截图）。

实测（8 个工具）：工具 schema **13 049 字**（description 5 455 + parameters 7 594）vs 提示段 **1 166 字 ≈ 9%**。

| 做法 | 为什么 |
|---|---|
| 提示段**从数据生成**（`PROMPT_GUIDE` / `PROMPT_RULES`），不要手写整段 | 手写的第二份副本**必然漂移**：实测一段提示**漏了 4 个版本** —— 两个后来加的工具在 AI 的开场提示里**根本没有指路** |
| 只放 schema 表达不了的：**决策 / 纪律 / 非工具能力** | 复述参数与返回值 = 花钱买漂移（而且参数已经在 schema 里了） |
| **加断言**：不在豁免表里的工具必须有一条「什么时候用」 | 加工具忘了补 → 测试**当场红**。豁免要**显式**列进 `PROMPT_SKIP`（如纯调试工具），否则会误报 |
| 顺手断言：**工具名与说明必须在同一行** | 不然渲染成「· 先用它定位…」，读者不知道「它」指谁（见 §11 最后一行） |

---

## 13. 版本与交付

- **一条 commit 一个版本**，CHANGELOG 每条带**实测数字**：
  不是「优化了性能」，而是「`18 917 B → 3 126 B（17%）」。
- 文档里写「**未实测**」比假装通过有价值：先写证据等级，再写结论。
- 交付时给出**可照抄的验收命令**（`node tests/*.mjs` 全绿 = 多少项），让人能自己复核。

## 附录：Windows / PowerShell 5.1 实测坑（本机）

这一节是 `win10` 这个名字的由来 —— 都是**在这台机器上真撞过**的：

| 坑 | 现象 | 怎么办 |
|---|---|---|
| **没有 heredoc** | `git commit -F - <<'X'` → `Missing file specification after redirection operator` | 提交信息**写文件**，再 `git commit -F <file>` |
| **`node -e` 的引号/正则会 PowerShell 吃掉** | 实测 `/" which\/.test(j)` 被解析成 `/" which\/.test(j)` 之外的别的东西 → `Invalid regular expression: missing /` | **要检查就写成测试文件**，别用 `-e`（顺带：这条检查本来就该是永久测试） |
| **管道会骗 exit code** | `node tests/x.mjs \| Select-Object -Last 3` 结束时报 `[exit code: 1]`，而 node 其实是 0 | 单独跑一次看 `$LASTEXITCODE`，别信管道 |
| **`Get-Content` 默认按 ANSI/GBK 解码** | 读 UTF-8 中文文件像乱码，误以为「文件是 GBK」 | 显式 `-Encoding UTF8`，或用 node / read 工具 |
| **重定向 stdout 走控制台代码页（本机 936）** | 子进程（.ps1）把中文标题输出给 Node → mojibake（实测「原神」→ `d4ad c9f1`） | 子进程侧把非 ASCII **转义成 `\uXXXX`**；或让 `.ps1` 保持纯 ASCII |
| **`$pid` 是只读自动变量** | 赋值报 `Cannot overwrite variable PID because it is read-only` | 换个名字（`$procId`） |
| **`Rename-Item` 前必须备份** | 技能/插件目录常**不在 git 里**，就是唯一副本 | 先逐文件 SHA 校验的备份；**备份不能放回 `skills/`**（带 `SKILL.md` 会被当成第二个技能加载）→ 放 `~/.dsh/_skill-backups/` |
| **改名要扫全机引用** | 技能目录、`skills/README.md`、工作区 `AGENTS.md`、插件源码注释、CHANGELOG 都可能写死了名字 | 写**脚本**做替换（保留 UTF-8 无 BOM、原子写）并**复查残留**；会话缓存（`storages/`）不要动 |
