# 发布文档内检流程（release-doc review）

> **什么时候用**：发版前、或任何要对外发布的文档（`README` / `.github/release-notes/*.md` / `CHANGELOG` / 迁移说明）改动之后。
> **谁来用**：写文档的人自己先跑一遍；AI 被要求"内检一份发布文档"时**按这个格式直接产出修订版**。
> **一句话**：**发布文档只服务读者与调用方，不服务维护者** —— 凡是"只有作者需要知道"的，一律删掉或移进开发文档。

## 默认读者（一切判断以他为基准）

**第一次拿到这个版本的使用者**，或**要调用这些工具的 AI Agent**。
他不在这台机器上、不关心仓库内部怎么管理、文档从哪挪到哪、谁帮谁做过什么。

## 第 0 步：先跑扫描（机械部分交给脚本）

```powershell
node scripts/scan-release.mjs            # 扫本仓：敏感信息 · 技能外信息 · 断链 · 日期水印
node scripts/scan-release.mjs --selftest # 正反例自检（确认扫描器本身没坏）
```

**扫四类**（`ERROR` 必须处理 / `WARN` 逐处判断 / `INFO` 多为内容）：

| 类别 | 抓什么 |
|---|---|
| 敏感信息 | 令牌 / 私钥 / 带凭据的 URL / 本机绝对路径（Windows 用户目录、POSIX 家目录）/ 游戏账号目录 / 内网 IP / 手机号 / 邮箱 |
| 技能外信息 | 工作区约定目录（桌面工作区根、案子目录、工作区脚本目录、插件包目录、上游只读克隆）+ 跨技能相对路径 |
| 断链 | markdown 链接与反引号路径**在本仓内解析不到**（双基解析：文件目录 + 仓根） |
| 日期水印 | `YYYY-MM-DD`（`INFO` —— 内容是日期就留，是水印就删） |

> 脚本**只报事实与位置、不下判决**；密钥一律**脱敏显示**（首尾各留 4 字符）。
> **技能外路径若确实是"读者必须知道的路径来源"** ⇒ 写成通用形式（`<工作区>/案子/<地图>/2.代码/`），别写本机绝对路径；
> **跨技能引用** ⇒ 写成"技能 `X` 里的 <文件>"，**别写成看起来能在本仓解析的相对路径**。

## 判定规则：一句话只有满足至少一条才保留

1. 影响**安装 / 升级 / 调用 / 配置 / 排障**；
2. 说明**兼容性 / 平台 / 版本 / 许可证 / 安全 / 破坏性变更**；
3. 给出**可执行命令、参数、默认值、返回值、错误语义**；
4. 是读者 / AI 完成当前任务**必须知道的边界、禁止事项、路径来源**；
5. 能帮读者判断"**我该用哪个工具 / 下一步做什么**"。

**不满足 ⇒ 默认删除。**

## 重点删除（发布文档里最高频的噪音）

- 迁移史、日期、文件从哪个目录挪到哪、为什么不在包里、谁帮的是谁；
- 内部路径、工作区文档、上游只读克隆、上游源码索引 —— 除非读者**必须去那里**才能用；
- "这讲的是……帮的是……不是……"这类**自我解释**；
- 括号套括号、破折号补充来源、许可结论、维护者备注；
- "不在本包，故不作链接"、"某年某月从 docs/ 挪过去"这类**对读者无动作**的信息；
- 重复的"详见 docs/xxx"、重复免责声明；
- 空泛评价："更可靠""更好用""不会过时""优化了体验"；
- 作者心路、决策过程、历史原因、内部考古。

## 保留并压缩

- 安装命令、版本要求、平台限制、许可证；
- 破坏性变更、迁移步骤、已知坑、安全警告；
- 工具名、op、参数、默认值、返回值、错误语义；
- AI Agent 执行所需的**路径来源、禁止写死、只写哪些目录**等硬边界；
- 真正**可达且读者需要**的链接 —— 写成「用途 + 直达链接」，不写迁移史。

## 每处只做四种处理之一

| 处理 | 含义 |
|---|---|
| **删除** | 不满足 5 条判定规则，且无读者动作 |
| **压缩成一句** | 有读者价值，但原文用了一段话 |
| **移到维护者文档** | 只对维护者有用 ⇒ 进 `CONTRIBUTING` / 开发文档（**别留在 README / CHANGELOG**） |
| **改成读者动作** | 原文是描述，改写成"读者该做什么"（命令 / 检查 / 参数） |

判断不了 ⇒ 标 `[待确认]`，**不要编造理由**。

## 输出格式（照抄这个骨架）

```markdown
## 内检结果
删除 X 处，压缩 Y 处，保留 Z 处，待确认 W 处。

## 修订版
<直接给可替换原文的全文>

## 删除/压缩清单
| 原文 | 类型 | 处理 | 理由 |
|---|---|---|---|

## 待确认
<最多 3 条>
```

## 最后自检（五问）

1. 修订版**是否更短、信息密度更高**？
2. 是否还有"**文档在解释自己**"的句子？
3. 是否还有内部路径、日期、迁移史、嵌套括号？
4. 每个链接读者**是否真的能到达**？不能就删。
5. 如果我是第一次用这个包的人或 AI，**只读修订版**，能不能完成安装 / 调用 / 排障？

## 本技能里的固定用法

- **发布面文档**：`README.md`、`.github/release-notes/v<版本>.md`、将来的 `CHANGELOG.md`。
- **开发文档**（维护者内容的家）：`references/`、`SKILL.md` —— 内检判"移到维护者文档"时，落这里。
- **与发版的关系**：内检在**打 tag 之前**跑；tag 之后再改文档 ⇒ 要么补一个补丁版本，要么在下一个版本的 notes 里说明（别悄悄改已发布的文档而不留痕）。
